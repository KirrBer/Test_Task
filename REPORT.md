# Отчёт: постобработка OCR паспорта РФ

## Подход

Целевая метка положительна, только если одновременно совпали все десять полей и паспорт действителен на 01.10.2026. Даже одна ошибка в поле делает документ отрицательным. Это соответствует цене ошибки из задания: неверно принятый документ опаснее отклонённого, хотя слишком строгий порог уменьшает долю автоматической обработки.

Для каждого документа строятся признаки из распознанных полей: уверенности OCR по полю и символам, число и длина строк, метрики качества снимка и источник изображения. Для MRZ учитываются наличие, успешность разбора и контрольных цифр, а также согласованность доступных значений с визуальной зоной: даты рождения, пола, номера документа и транслитерированных ФИО. Код подразделения дополнительно сопоставляется со справочником; названия органа используются для оценки географического и текстового сходства. Эти сигналы не заменяют проверку полей, а помогают оценить риск ошибки всего документа.

Тексты нормализуются перед сравнением: пробелы приводятся к единому виду, для отдельных типов полей используются форматирование и разбор даты. CatBoost оценивает вероятность того, что все десять нормализованных полей совпадают с разметкой и паспорт действителен на контрольную дату. Если вероятность достигает порога режима, документ принимается и возвращаются распознанные значения; иначе он отклоняется.

Обучающая выборка содержит 3000 документов; положительный класс составил 1629 документов (54,3%). Для выбора параметров CatBoost применялась Optuna, качество и рабочие пороги оценивались с помощью 5-fold кросс-валидации. Разделение на фолды позволяет получать out-of-fold (OOF) оценки для документов, которые не участвовали в обучении соответствующей fold-модели. Порог выбирался отдельно для каждой целевой precision. Была найдена одна ошибка в разметке(строка 2183, ошибка в фамилии), но их может быть больше.

Test содержит 2000 документов. Его разметка недоступна, поэтому таблица ниже показывает фактическое число принятых документов и прогнозируемое число ошибок, но не измеренную точность на test. Все три режима используют один интерфейс запуска и записывают решения в формате `answers.jsonl`.

## Режимы

| Режим | Цель настройки | Принято на test | Прогноз ошибок на test |
|---|---|---:|---:|
| 98 | precision 0,98 | 619 (30,9%) | 10 - 15 |
| 99 | precision 0,99 | 312 (15,6%) | 2 - 5   |
| 100 | precision 1,00 | 168 (8,4%) | 0 - 2   |

Для режима 98 сохранённая OOF-оценка precision равна 0,9802. При переносе этой оценки на 619 принятых документов ожидается около 12 ошибок: `619 × (1 − 0,9802)`. Это статистическая оценка, а не гарантия.

Для режима 99 OOF-оценка precision равна 0,9906, recall — 0,3241. При переносе precision на 312 принятых документов точечный прогноз составляет около 3 ошибок: `312 × (1 − 0,9906)`. Этот режим принимает примерно половину документов режима 98, но ожидаемое число ошибочных принятий также ниже.

Для режима 100 OOF-оценка precision равна 1,00, recall — 0,2099; на OOF при выбранном пороге FP не наблюдалось. Поэтому точечный прогноз — 0 ошибок среди 168 принятых test-документов. Диапазоны в таблице являются плановыми оценками неопределённости, а не формальными доверительными интервалами. Особенно важно не трактовать ноль FP на OOF как доказательство нулевого риска на новых данных: при небольшом числе принятий даже несколько ошибок заметно меняют precision.

Различие режимов — в строгости порога, а не в формате результата. При выборе режима нужно учитывать стоимость ручной пересъёмки и цену ошибочного принятия: `98` ориентирован на больший охват, `99` представляет промежуточный вариант, `100` принимает только наиболее уверенные документы. Если ошибочное принятие недопустимо, режим `100` соответствует цели настройки лучше, однако и он требует проверки на независимой размеченной выборке.

## Вывод

Режим 98 принимает больше документов, но имеет и наибольшее ожидаемое число ошибок. Режим 99 принимает 312 документов с точечным прогнозом около 3 ошибок и может быть компромиссом между охватом и риском. Режим 100 принимает 168 документов; точечный прогноз по OOF — 0 ошибок, ценой меньшего охвата. Ни один режим не доказывает отсутствие ошибок на test. Выбор режима необходимо осуществить в зависимости от соотношения цены ошибочного принятия к цене ошибочного отказа. Так как в задаче это не было описано, заранее угадать какой режим будет выгоднее невозможно.


Запуск режимов(по умолчанию стоит режим 100):

```powershell
python postprocess.py data/test_predictions.jsonl answers.jsonl --mode 98
python postprocess.py data/test_predictions.jsonl answers.jsonl --mode 99
python postprocess.py data/test_predictions.jsonl answers.jsonl --mode 100
```
