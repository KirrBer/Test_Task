# Постобработка OCR паспортов РФ

Скрипт оценивает риск ошибки распознавания каждого документа и принимает или отклоняет его. Принятый документ включает значения всех 10 полей. Модель также учитывает, действителен ли паспорт на 01.10.2026.

## Запуск

Требуется Python и зависимости из `requirements.txt`. В Windows PowerShell установите их так:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Запустите постобработку на test-данных:

```powershell
python postprocess.py data/test_predictions.jsonl answers.jsonl --mode 100
```

Режимы отличаются порогом принятия:

| Режим | Назначение | Принято на test | Прогноз ошибок среди принятых |
| --- | --- | ---: | ---: |
| `98` | Больше охват, целевая precision 98% | 619 (30,9%) | 10–15 |
| `99` | Промежуточный вариант, целевая precision 99% | 312 (15,6%) | 2–5 |
| `100` | Наиболее строгий порог, целевая precision 100% | 168 (8,4%) | 0–2 |

Режим `100` используется по умолчанию. Чтобы выбрать другой режим, укажите `--mode 98` или `--mode 99`. Модели загружаются из `models/mode_<режим>/`; справочник подразделений берётся из `data/subdivisions.csv`.

Скрипт создаёт `answers.jsonl`: одна JSON-строка на документ с `doc_id` и решением `accept` или `reject`. Значения `fields` записываются только для принятых документов.

Прогнозы ошибок рассчитаны по кросс-валидационным оценкам и не являются измеренной точностью на test или гарантией отсутствия ошибок. Подробности и методика приведены в [REPORT.md](REPORT.md).

## Проверка на размеченных данных

Чтобы получить ответы для обучающей выборки и сравнить их с разметкой:

```powershell
python postprocess.py data/train_predictions.jsonl train_answers.jsonl --mode 100
python evaluate.py train_answers.jsonl data/train_labels.jsonl
```

`evaluate.py` сравнивает поля с разметкой, но отдельно не проверяет действительность паспорта.
